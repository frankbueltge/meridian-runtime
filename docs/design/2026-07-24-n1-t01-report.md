## Implementation summary

A read-only, DB-free validation harness that turns the K1-T04/K1-T06
model-collapse blind-vs-pipeline verification set into a stratified,
hash-anchored inter-instance agreement report — `mrr validate agreement`.

1. **`packages/domain/mrr/domain/agreement.py`** — pure, dependency-free
   metric core (no numpy/scipy/scikit-learn/statsmodels): `align_ratings`
   (typed `MismatchedRatersError` naming the offending items on a set
   mismatch), `confusion_matrix` (explicit, caller-supplied category order;
   typed `DuplicateCategoryError`/`UnknownCategoryLabelError`),
   `observed_agreement`, `majority_baseline` (named reference rater),
   `cohen_kappa`, `weighted_kappa` (linear/quadratic), 
   `krippendorff_alpha_nominal` (two-coder nominal alpha via the symmetric
   coincidence matrix), and `per_category_prf`. Every accumulation uses
   `fractions.Fraction` internally for exact rational arithmetic (no float
   drift, exact zero-denominator checks), converting to `float` only at the
   final result. Every "no expected-chance variation" edge case (kappa,
   weighted kappa, alpha alike) returns `value=None` with
   `reason="undefined: no expected-chance variation"` — never a
   `ZeroDivisionError`, never a fabricated `0.0`/`1.0`. A zero-support
   category's precision/recall/F1 is `None` with `reason="no support"`.
2. **`packages/domain/mrr/domain/agreement_report.py`** — a Pydantic v2
   `MRRModel` (`extra="forbid"`) projection, mirroring
   `mrr.domain.research_report`'s pure model+renderer split: `AgreementReport`
   (a fixed honesty header — `measures_reliability_not_validity: Literal[True]`,
   a reliability-not-validity note, the named reference rater and its own
   note, the crosswalk path/sha256, an ORDERED tuple of `StratumReport`
   sorted by `stratum_id`, and `pooled_note`) with **no field anywhere that
   could hold a pooled cross-stratum kappa** — a structural guarantee, not a
   nullable field nobody populates. `build_stratum_report` computes
   `below_power` (any declared category's count, either rater, below 20).
   `render_markdown`/`render_json` are pure and deterministic (no wall
   clock; bullet-block Markdown, never a `|`-table, mirroring
   `research_report`'s own disclosed injection-safety choice for free-text
   titles).
3. **`services/control_plane/mrr/services/validation/service.py`** —
   `ValidationService.build_report(analysis_set_path)`: reads the crosswalk
   JSON, resolves its declared `source_files` (relative to the crosswalk's
   OWN directory, never the caller's cwd), reads the two source files live,
   validates the declared alignment is total (typed
   `MissingAlignedItemError`/`TitleMismatchError` naming the gap — never a
   silent partial), maps each rater's raw label into the common space via
   the crosswalk's declared `label_map` (typed `UnmappedLabelError` if a raw
   label has no honest mapping), invokes the R1 core per stratum, and
   assembles the report. Opens no database connection, constructs no
   repository. Every crosswalk/source-file shape problem raises the typed
   `AnalysisSetFileError` (never a bare `KeyError`/`TypeError`).
4. **`services/control_plane/mrr/services/cli/validation_main.py`** +
   **2 lines in `cli/main.py`** (one `validation_main.register_validation_
   subcommand(subparsers)` call, one `if args.command == "validate":
   return validation_main.run_command(args)` dispatch — plus the
   necessarily-accompanying import-tuple addition, matching every prior
   CLI-registration precedent in this file) — `mrr validate agreement
   --analysis-set <path> [--format md|json] [--output <path>]`. NFR-012
   ordering: `--output` conflict (exit 3) checked first, then
   `ValidationService.build_report` (file-shape failures -> exit 2; every
   other typed refusal, including an undefined kappa/alpha which is
   correctly NOT a refusal at all — see R1 — -> exit 3 only for genuine
   alignment/mapping problems). Atomic `os.replace` for `--output`; stdout
   when `--output` is omitted.
5. **`corpora/model-collapse/verification/agreement-crosswalk.v1.json`** —
   the declared, committed crosswalk (R3): item alignment (`blind_item` <->
   `corpus_entry_id` <-> `title`) transcribed verbatim from
   `comparison.md`'s own table (cross-verified programmatically against the
   real `corpus-entries.json`/`blind-returns.json` at authoring time — all
   18 items align by title with zero mismatches), the per-stratum raw-label
   -> common-space label map, the per-stratum ordered category list
   (alphabetical, which for the instantiation stratum also reads as an
   ordinal hedge scale: `instantiates`, `qualifies`, `references`), a
   `provenance` block naming `comparison.md` and its freeze commits
   (`dab655c`/`f4136f1`), and `source_files` (paths relative to the
   crosswalk's own directory). Raw labels are **not** duplicated in the
   crosswalk — they are read live from the two source files every run, so
   the crosswalk can never silently drift stale.

## A documented, provable specification conflict (AT1 / the theory stratum)

The packet's own objective/AT1 text states the report "reproduces
`comparison.md` exactly: observed agreement = 1.0 and Cohen's kappa = 1.0
per stratum." Running the real computation over the committed corpus shows
this holds **exactly** for the **instantiation** stratum (n=15) but **not**
for the **theory** stratum (n=3): all three theory papers are classified
`supports` by BOTH raters — the other declared category, `contradicts`, has
**zero** support on both sides. By Cohen's kappa's own definition this makes
`p_e` (chance-expected agreement) exactly `1`, so
`kappa = (p_o - p_e) / (1 - p_e)` divides by zero: mathematically
**undefined**, not `1.0`. Krippendorff's alpha and both weighted-kappa
variants are undefined for the identical reason (a zero expected-disagreement
denominator).

This is **not a bug**: it is precisely the "single category used by both
raters" edge case R1 itself names and requires be reported as
null-with-reason, "never a fabricated 0.0/1.0" (AGENTS.md rule 12). Per
stop_condition 2 ("going green would require weakening an edge-case rule ...
may not be softened"), this implementation reports the mathematically honest
result — `cohen_kappa.value is None`,
`reason="undefined: no expected-chance variation"` — for the theory stratum,
rather than forcing `1.0` to match the packet's summary prose literally.
**Observed agreement (p_o) = 1.0 DOES hold for both strata**, exactly as
`comparison.md`'s "18/18 agreement" claims; it is specifically the
chance-corrected statistic the theory stratum's degenerate, zero-variation
sample cannot support. Asserted directly in
`tests/contract/test_agreement_acceptance.py::test_at1_theory_stratum_kappa_is_honestly_undefined_not_fabricated_one`.

A second, smaller finding surfaced while writing the property-test suite (see
below): Cohen's kappa and Krippendorff's alpha do **not** always share a sign
on non-perfect-agreement data — `matrix=((0,0,0),(1,0,0),(2,0,1))` gives
kappa ≈ +0.0769 but alpha ≈ −0.1053 (both correct for their own,
differently-corrected small-sample formulas). The property suite asserts
sign-sharing only under perfect multi-category agreement (where both are
trivially `1.0`), per the packet refinement below.

## Packet refinement (as instructed by the assigning session)

The task instructions explicitly pre-authorized a refinement to R6's property
tests, given the exact tension above: **do not** assert `alpha == kappa`
strictly (they differ by alpha's `(n-1)` small-sample correction). Instead:
`alpha ∈ [-1, 1]`; `alpha == 1.0` iff perfect agreement with >1 category
used; `kappa ∈ [-1, 1]`; `kappa` symmetric under swapping raters; `kappa ==
1.0` iff perfect agreement with >1 category used; `alpha`/`kappa` share sign
and both equal `1.0` **on perfect agreement**. Implemented exactly this way
in `tests/property/test_agreement_properties.py` (see that module's own
docstring for the full rationale, including the sign-sharing counterexample
above, found by hypothesis when an earlier, unconditioned version of that
property was tried and correctly falsified).

## Known limitations

- **Reliability, not validity** (by design, not a gap): the blind rater
  (K1-T06) is an independent instance, not a human gold standard. This
  report cannot and does not claim anything about whether the shared
  classification is *correct* — only that two independent instances agree.
  Validity against human labels is named, not built, as N1-T02.
- **The theory stratum's kappa/alpha are structurally uninformative** (n=3,
  zero category variation) — see the documented spec conflict above. This
  is inherent to the real data, not a defect in the metric core; the report
  makes this honestly visible (null-with-reason) rather than hiding it
  behind a headline number.
- **n=15/n=3 are both below the documented 20-30/category power threshold**
  (A4) — `below_power=True` on both strata, by design, so a reader can never
  mistake this perfect-agreement sample for publication-grade evidence.
- **The corpus <-> sealed-EvidenceMatrix faithfulness** was spot-verified at
  derivation time (`theory-shumailov -> supports` in both), not re-asserted
  as a CI test here — CI has no access to the real archival PostgreSQL
  schema (per the packet's own derived_decision (f)). This packet validates
  the COMMITTED corpus files' internal consistency (the crosswalk's
  declared alignment against the live corpus/blind files), not their
  fidelity to the original sealed database objects.
- **Title cross-checking is best-effort**: `blind-returns.json`'s `papers`
  array carries no `title` field (only `works` does), so the
  `TitleMismatchError` check for the three theory-stratum items validates
  only against `corpus-entries.json`'s own title, not a second, independent
  blind-side title.

   stratum** — see the dedicated section above. Resolved by reporting the
   mathematically honest null-with-reason result, per R1's own edge-case
   contract and stop_condition 2, rather than fabricating `1.0`.
2. **R6's "alpha == kappa relationship holds ... within tolerance"** does
   not hold even approximately in the theory stratum's degenerate case (both
   are undefined there, for structurally different reasons), and the two
   statistics do not universally share a sign even on non-degenerate,
   non-perfect-agreement data. Resolved per the assigning session's own
   pre-authorized packet refinement (see above), which this implementation
   follows exactly, with one additional, concretely falsifying counterexample
