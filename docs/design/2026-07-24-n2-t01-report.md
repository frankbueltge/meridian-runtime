## Implementation summary

A read-only, no-network, DB-free citation-audit harness that classifies
every citation in a committed manifest against a committed resolution
snapshot as `resolved` / `not_found` / `title_mismatch` / `unverifiable` /
`malformed` — never collapsing those five — and renders a deterministic
report that verifies a reference EXISTS and is correctly TITLED, explicitly
NOT that it SUPPORTS the claim it is cited for. First (and, for T01, only)
target: the eight primary sources cited by the public `/e2e-automation`
survey — a survey warning of citation fabrication surviving its own
citations being checked.

1. **`packages/domain/mrr/domain/citation_audit.py`** — pure,
   dependency-free classification core (stdlib only: `re`, `string`,
   `dataclasses`, `collections.abc`, `typing`, `urllib.parse`):
   - `is_wellformed_arxiv` (`YYMM.NNNNN[vN]`, month constrained to 01-12),
     `is_wellformed_doi` (`10.\d{4,9}/\S+`), `is_wellformed_url` (http(s)
     scheme + non-empty host, no embedded whitespace) — implemented from the
     packet's own exact patterns, not improvised.
   - `normalise_title` (casefold, collapse internal whitespace to one space,
     strip leading/trailing whitespace and surrounding punctuation — ASCII
     `string.punctuation` plus curly quotes/dashes/ellipsis/guillemets) and
     `title_matches`, returning a named `TitleMatchResult(matches, method)`
     (`"exact"` / `"prefix"` / `"no_match"`) — never a bare bool guessed from
     a fuzzy ratio.
   - `classify_citation(entry, resolution)` — the packet's own exact
     five-step order: (1) malformed, decided BEFORE the snapshot is
     consulted; (2) a missing resolution raises the typed
     `MissingResolutionError` naming the `citation_id`; (3) `unverifiable`
     (checked before `resolved`, so it wins even over `resolved=false` —
     see "A resolved clarification" below); (4) `not_found`
     (`resolved=false`); (5) `title_mismatch` vs `resolved` depending on
     `title_matches` when a `claimed_title` is declared. `classify_citations`
     sorts the whole batch by `citation_id` for a deterministic,
     caller-order-independent result.
2. **`packages/domain/mrr/domain/citation_audit_report.py`** — a Pydantic v2
   `MRRModel` (`extra="forbid"`) projection, mirroring
   `mrr.domain.agreement_report`'s pure model+renderer split:
   `CitationAuditReport` (a fixed honesty header —
   `verifies_existence_not_support: Literal[True]`, an existence-note naming
   N2-T02/N2-T03 as out of scope by name, `audit_target`, `manifest_path`,
   `snapshot_path`, `snapshot_sha256`, per-status `SummaryCounts`, and an
   ORDERED tuple of `CitationVerdictRow` sorted by `citation_id`). Not a
   `BaseObject`; no `schemas/*.schema.json` mirror; never passed to
   `ObjectRepository.insert_revision`. `render_markdown`/`render_json` are
   pure and deterministic (no wall clock) — Markdown renders an actual
   `|`-delimited table (task-packets/N2-T01.yaml R4's own explicit
   requirement, unlike `agreement_report`'s bullet-block choice), with
   `|`/newline escaping for any cell value.
3. **`services/control_plane/mrr/services/citation_audit/service.py`** —
   `CitationAuditService.build_report(manifest_path, snapshot_path)`: reads
   and parses both files (typed `CitationAuditInputError` naming the exact
   shape problem — missing key, wrong JSON type, non-boolean `resolved`/
   `unverifiable` — never a bare `KeyError`/`TypeError`), computes the
   snapshot's sha256 over its raw file bytes, classifies every manifest
   citation via the R1 core, and builds the report. Opens no database
   connection and no network connection; the only I/O is reading the two
   given filesystem paths.
4. **`services/control_plane/mrr/services/cli/citation_audit_main.py`** + **2
   lines in `cli/main.py`** (one `citation_audit_main.register_audit_
   subcommand(subparsers)` call, one `if args.command == "audit": return
   citation_audit_main.run_command(args)` dispatch — plus the
   necessarily-accompanying import-tuple entry, matching every prior
   CLI-registration precedent in this file) — `mrr audit citations
   --manifest <path> --snapshot <path> [--format md|json] [--output
   <path>]`. NFR-012 ordering: `--output` conflict (exit 3) checked first,
   then `CitationAuditService.build_report` (file-shape failures -> exit 2;
   `MissingResolutionError` -> exit 3). Atomic `os.replace` for `--output`;
   stdout when `--output` is omitted. A standalone `build_parser()`/`main()`
   also works via `python -m mrr.services.cli.citation_audit_main citations
   ...` (verified manually, see below).

The committed fixtures (`corpora/e2e-survey/citations.manifest.json`,
`corpora/e2e-survey/verification/resolution-snapshot.json`) were **not
touched** — read-only throughout, per R3/forbidden_changes/stop_conditions.

## A clarification, not a conflict: `unverifiable` outranks `not_found` even when `resolved=false`

The packet's R1 prose paraphrase ("else if the snapshot marks it not
resolved, `not_found`; else if the snapshot resolved it but marks it
metadata-only/paywalled-unverifiable, `unverifiable`") reads, taken alone, as
if `unverifiable` only applies when `resolved=true`. The packet's own
separate, explicitly-numbered "Exact classification order" section — labeled
"implement these; do not improvise" — resolves this precisely: step 3
(`unverifiable`) is checked **before** step 4 (`not_found`), so a resolution
with `unverifiable=true` classifies as `unverifiable` regardless of its own
`resolved` value. This implementation follows the numbered, authoritative
order (also matching the derivation doc's own framing of `unverifiable` as
"metadata-only / paywalled / could-not-determine — never counted as a pass
or a fail", which is a statement about the flag alone, not about `resolved`
first). Exercised directly by
`tests/unit/domain/test_citation_audit.py::test_classify_citation_unverifiable_overrides_not_resolved_too`.
The real e2e-survey snapshot has no `unverifiable` entries at all, so this
has no effect on the acceptance numbers — flagged here per AGENTS.md's
"any specification conflict discovered" delivery requirement, even though it
is a clarification of an internal ambiguity rather than a hard conflict.

## Known limitations

- **Existence is not support** (by design, not a gap): a `resolved` status
  means the identifier resolves to a real registered work with a matching
  title — it says nothing about whether the resolved source actually
  supports the claim the survey cites it for. That check (N2-T02) and
  number-consistency checking (N2-T03) are both out of scope here, and the
  report's own honesty header says so on every render.
- **The real fixture never exercises `not_found`/`title_mismatch`/
  `unverifiable`/`malformed`** (all 8/8 resolve cleanly) — those four
  statuses are proven correct only against hand-built synthetic unit
  fixtures (AT4), per the packet's own derived_decision (f). This is
  expected, not a coverage gap: the real e2e-survey data genuinely has no
  problem citations to surface.
- **The resolution snapshot is a point-in-time, committed fetch result**,
  not re-verified live by this tool — by design (derived_decisions (b)): if
  a cited paper were later retracted or an arXiv id were withdrawn, this
  report would still say "resolved" until the snapshot is regenerated
  (N2-T02's gated fetch script, not built here).
- **`title_matches`'s prefix rule is intentionally permissive**: any cited
  label that is a prefix of the resolved title (or vice versa) counts as a
  match — chosen because most of this fixture's own citations carry no
  `claimed_title` at all (the survey cites by descriptive label + URL, not
  by title), so this rule is exercised only by synthetic unit tests here,
  not by the real acceptance data.
