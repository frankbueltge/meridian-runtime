## Implementation summary

`mrr report render --database-url … --crate-id … --output … --format md|html --disclosure
internal|public [--classification-file …]` renders a deterministic Markdown or HTML narrative
report from one sealed `EvidenceCrate`'s export closure — the SAME closure `mrr export ro-crate`
ships, not a second, competing definition of "what belongs to this run's record". Sections, fixed
order, always present (an empty one renders `(none recorded)` rather than disappearing): header,
methods, claim table (every claim's status/uncertainty/evidence/counterevidence/dependencies, plus
EVERY `VerificationResult` targeting it — two disagreeing recommendations render as two rows,
explicitly marked "disagreement on record", never merged or averaged), evidence map, corrections
(unresolved critical ones prefixed and structurally unomittable), known unknowns, failures,
provenance summary. No model/LLM call anywhere — a hand-rolled, pure template renderer, structurally
incapable of inventing a citation since every urn it emits traces back to a value actually read from
the closure or a correction row (R5's own mechanical test, `rendered_urns ⊆ source_urns`).

Four pieces:

- **`packages/domain/mrr/domain/research_report.py`** (new, pure, no I/O, no repository types) — the
  frozen `ResearchReport` model tree, `build_report(...)` (pure model construction from already-
  loaded closure bodies), and `render_markdown`/`render_html` (hand-rolled, no markdown/html
  library — `html.escape`-equivalent five-character substitution table only). Fail-closed redaction
  for the public disclosure reuses `mrr.domain.public_correction_view.build_public_claim_row`
  verbatim for the Claim assertion, and a byte-for-byte restatement of that module's own fail-closed
  formula (`_all_attested_public`) for the three free-text categories R3 names that module was never
  scoped to cover (finding statements, failure messages, known-unknown strings) — see the module's
  own docstring, "Why this module owns the report's own redaction too". One shared `AlwaysPublic
  Attestation`/`ALWAYS_PUBLIC_ATTESTATION` singleton drives internal disclosure through the SAME
  fail-closed code path (every id attested `"PUBLIC"`) rather than a second, separately-written
  "show everything" branch — reused by `ReportService` too, for its own `build_public_correction_view`
  call.
- **`services/control_plane/mrr/services/export/service.py`** (R2 extraction) —
  `ExportService.resolve_closure(crate_id) -> ExportClosure` is the exact closure-resolution half of
  `export`'s prior body (crate resolution, the three `_CRATE_URN_ARRAY_FIELDS`, the per-claim
  provenance BFS, R2d verification discovery), MINUS the artifact-byte fetch; `export` now calls it
  and performs only the byte-fetch/plan/write steps on top. No line of the closure algorithm changed.
- **`services/control_plane/mrr/services/report/service.py`** (new) — `ReportService`, read-only,
  composes `ExportService.resolve_closure` (via an internal `ExportService` built with a
  `_NeverInvokedArtifactStore` stand-in — the report never fetches artifact bytes, so there is no
  `--artifact-root` flag and no real store is ever constructed) and `ProjectionService
  .build_public_correction_view`/`.build_provenance_map` (corrections discovery, crate-scoped by a
  plain filter over that system-wide method's own output; per-claim provenance, a second call to the
  same already-tested BFS method since the closure's own flattened union cannot be regrouped by
  claim).
- **`services/control_plane/mrr/services/cli/report_main.py`** — the thin CLI, ordered per
  MRR-NFR-012 (`--output` conflict, then `--classification-file` required-with-public/forbidden-
  with-internal/read/parsed/validated, then database reachability, then exactly one `ReportService`
  call plus one render call); exit codes `0`/`2`/`3`; atomic write (temp file + `os.replace`).
  `main.py` gained exactly one additive registration block, mirroring the export/verification
  precedent.

## Security / privacy implications

None new beyond E8-T01/T02's own already-disclosed stance. The report path is read-only against
already-sealed, already-persisted state; no credential, secret, or private key is read or written.
Unlike the export path (whose own "Known limitations" already flags "No classification/redaction
gate" as an open item for a future packet), THIS packet is exactly that redaction gate for the
narrative projection: the public disclosure is fail-closed by construction — a stored free-text
string is visible only when every object id it depends on is explicitly attested `PUBLIC` by the
caller, never inferred, never defaulted, and an empty or missing attestation redacts identically to
an attestation naming a non-`PUBLIC` level. The classification attestation itself remains a
caller-supplied file (never a stored, service-computed field) — the same ADR-0010-staged bridge
E6-T05 established, now surfaced as an explicit, required CLI argument rather than silently trusted.
`partner-restricted` disclosure (MRR-FR-103's third projection) is NOT implemented here — see
derived_decisions (c) and "Known limitations" below.

## Known limitations

- **`partner-restricted` disclosure is a named gap, not a silent one** (derived_decisions (c)): the
  `Classification` vocabulary has no partner level and the partner-relationship machinery lives in
  the transfer layer; inventing a mapping here would guess governance the spec has not written.
  Deferred to E8-T04/an E5-transfer integration or an ADR.
- **"Every discovered correction" is, in this implementation, exactly the unresolved-critical set**
  (`ProjectionService.build_public_correction_view`'s own population): `ProjectionService` offers no
  OTHER public correction-listing method within this packet's `allowed_paths` (only per-claim
  `unresolved_correction_ids` and `build_public_correction_view` itself, both scoped to MRR-FR-095's
  population). A resolved or non-critical correction is therefore outside what `mrr report render`
  can currently discover at all — flagged in both `mrr.domain.research_report`'s and
  `mrr.services.report.service`'s own module docstrings, not silently narrowed. Widening correction
  discovery to every status/severity would require a new `ProjectionService` method, out of this
  task's `allowed_paths`.
- **The "run's declared protocol/parameters" reading is a disclosed judgment call** (R1(2)'s own
  prose admits more than one parse): implemented as three parts — `RunManifest.parameters` rendered
  verbatim when the `RunManifest` happens to be part of THIS crate's closure (not guaranteed — it is
  reached only via the R2(c) field-reference BFS from an included `EvidenceAnchor.run_id`), the
  crate's own `artifacts` array (`ArtifactRef` — always available, needs no `RunManifest`
  resolution), and the crate's own `environment` block (also always available). An alternative
  reading — treating `RunManifest.parameters`' own embedded artifact urns as "the" artifact-urns-
  with-hashes list (mirroring `mrr.domain.prov_mapping.run_manifest_relations`'s own recursive scan)
