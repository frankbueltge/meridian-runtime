## Implementation summary

A SECOND closure root alongside the crate — the export/report machinery, which was entirely crate-rooted
by design (E8-T01's own "one closure, two consumers"), now also resolves the claim graph directly, with no
crate at all. Six files, additive by design, zero forbidden-path edits:

1. **`ExportService`** (`services/control_plane/mrr/services/export/service.py`) gains
   `resolve_closure_from_claims(claim_ids: Sequence[Urn] | None = None) -> ExportClosure` and
   `export_from_claims(claim_ids, output_dir) -> ExportResult`. The crate-rooted `resolve_closure`/`export`
   are refactored into a **shared private core** — `_resolve_provenance_and_verifications` (R2c's per-root
   provenance BFS plus R2d's event-log-scan verification discovery, extracted VERBATIM from the prior inline
   body) and `_write_closure` (R3's artifact-byte fetch + `build_export` + atomic write) — with no line of
   the original algorithm changed; `resolve_closure(crate_id)`'s public signature and behavior are
   byte-identical to before. The claim-rooted path adds exactly one new piece of traversal logic, added HERE
   (never in `mrr.services.projection.service`, forbidden and reused verbatim): `_resolve_declared_reference_fields`,
   a FIXED, fact-locked per-kind map —

   ```
   Claim               -> evidence_relations, counterevidence_relations, verification_ids, source_family_ids
   EvidenceAnchor       -> source_record_id, run_id   (each only when non-empty)
   VerificationResult   -> evidence_inspected
   ```

   — resolved via `ObjectRepository.get_latest` (fail-fast: an unresolved referenced urn raises
   `ObjectNotFoundError` naming it), transitively to fixpoint, PLUS `build_provenance_map(claim)` per root
   claim (typed-edge enrichment: ruling, protocol — reused, not re-derived). `ExportClosure.crate_id` becomes
   `Urn | None`; a claim-rooted closure carries `crate_id=None` and an EMPTY `artifact_refs` (no artifact
   bytes ship — the artifacts are the run's INPUTS, the research OUTPUT is the claim graph). A zero-claim
   root (`--all-claims` on an empty schema, or an explicit empty list) refuses via a new
   `NoClaimsToExportError(DomainError)`, never a silent empty bundle.
2. **`mrr.domain.ro_crate`** — `build_ro_crate_metadata`/`build_export` gain `crate_urn: str | None`. `None`
   selects the no-crate mode: `datePublished` becomes `_max_created_at(plan.objects)` (the MAXIMUM
   `created_at` across every exported object, returned VERBATIM — never reformatted, never wall-clock-read),
   and no `prov:wasGeneratedBy` is emitted (harmless: `plan.artifacts` is always empty for a claim-rooted
   export). Every other entity-shaping rule (contextual entities, PROV types, R3 stubs) is already generic
   over kind and untouched. The crate-rooted branch (`crate_urn` given) is BYTE-IDENTICAL to pre-E8-T06
   output — reached only under an explicit `if`, every line unchanged.
3. **`mrr.domain.research_report`** — `build_report` gains `crate_id: str | None = None`; `HeaderSection`
   gains `root: Literal["crate", "claim graph"]`, `run_urns: tuple[str, ...]`, `claim_count: int`, and its
   five crate-specific fields (`crate_urn`/`run_urn`/`run_state`/`practice_id`/`content_hash`) become
   `Optional`; `MethodsSection.run_urn` becomes `Optional`. Claim-rooted: section 1 shows `root = "claim
   graph"`, every reached `RunManifest` (0+, honestly — the real K1-T04 fixture reaches none), the claim
   count, and `created_at` = the same max-created_at computation (independently authored here, not imported
   — `research_report.py`/`ro_crate.py` are both pure leaves forbidden from depending on each other).
   Sections 2 (methods)/6 (known unknowns)/7 (failures) — the three sections that read `EvidenceCrate`-only
   fields — degrade to the SAME empty values a crate-rooted report already renders for a minimal crate (no
   new rendering branch for those); sections 3 (claim table)/8 (provenance summary) switch their claim-id
   population to "every `Claim`-kind object in `object_bodies`" ONLY in the `crate_id is None` branch, never
   touching the crate-rooted branch's own `crate_body.get("proposed_claims")` read; sections 4 (evidence
   map)/5 (corrections) were ALREADY generic and needed no change at all. Both renderers gate the header
   difference (and the title line) behind one `model.header.root` check, mirroring E8-T05's own established
   "one `if` at the top" convention for the release banner. A real bug was found and fixed during this work:
   the HTML renderer's `<title>` line read `model.header.crate_urn` directly, unguarded by the `root` check
   used everywhere else — for a claim-rooted report this would have printed `<title>Research report —
   None</title>`. Caught by `test_claim_rooted_render_html_shows_root_and_disagreement`, fixed to read the
   same `title_subject` variable the `<h1>` line already uses.
4. **`ReportService`** gains `render_from_claims(claim_ids, *, disclosure, classification_by_object_id=None)`,
   composing `resolve_closure_from_claims` instead of `resolve_closure`, otherwise mirroring `render`'s own
   wiring line for line — same corrections crate-scope filter (already generic), same per-claim
   `build_provenance_map` composition (keyed now by every claim the closure contains). Deliberately carries
   NO `release_id` parameter: release stays crate-rooted (reviewer_resolution (4)) — `mrr report render`
   never exposed `--release-id` at the CLI for the crate-rooted path either, so this omission changes no
   currently-reachable behavior.
5. **CLI** (`export_main.py`/`report_main.py`) — both `ro-crate`/`render` gain a mutually-exclusive,
   `required=True` argparse group: `--crate-id` (unchanged) | `--claim-id` (repeatable, `action="append"`) |
   `--all-claims` (`store_true`). `export_main.py`'s `--artifact-root` becomes `default=None` at the argparse
   level and a MANUAL post-parse shape check: REQUIRED with `--crate-id`, FORBIDDEN with
   `--claim-id`/`--all-claims`. **Disclosed exit-code choice** (the packet's own AT5 names this a "usage
   refusal" without pinning an exit code): exit `2`, mirroring `report_main.py`'s own directly-analogous
   `--classification-file` required-with-public/forbidden-with-internal precedent (also exit 2) — the
   closest, most literal precedent in this codebase, chosen over exit 3 (reserved for refusals downstream of
   a successful dependency check). The exit-0 JSON line on both commands gains `"root"`
   (`"crate"`/`"claims"`) and `"claim_ids"` — purely additive; every crate-rooted invocation's pre-existing
   keys keep their pre-existing values. `main.py` untouched (no new subcommand — both existing ones gained
   flags, exactly as instructed).
