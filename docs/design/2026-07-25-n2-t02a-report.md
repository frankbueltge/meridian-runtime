## Implementation summary

A standalone, stdlib-only, gated fetch script OUTSIDE the runtime
(`scripts/fetch_citation_resolutions.py`) that resolves every citation in a
committed manifest against the two open, keyless metadata APIs (arXiv,
Crossref) behind a hard https + host allowlist, and writes a deterministic
`citation-resolution-snapshot.v1` document — committed once as
`corpora/research-records/verification/resolution-snapshot.json`. The
snapshot is then audited with the UNCHANGED, frozen N2-T01 evaluator
(`mrr audit citations`). This packet changes **no runtime code** — nothing
under `packages/**` or `services/**` was touched.

1. **`scripts/fetch_citation_resolutions.py`** (new, ~600 lines incl.
   docstrings): imports nothing from `mrr.*` (checked by a dedicated AST
   boundary test) and nothing beyond the Python standard library
   (`argparse`, `json`, `os`, `re`, `sys`, `urllib.request`, `urllib.parse`,
   `urllib.error`, `xml.etree.ElementTree`, `collections.abc`, `dataclasses`,
   `datetime`, `pathlib`, `typing`) — no new dependency.
   - `_check_allowlisted`/`_open_url`: the ONE choke point every outbound
     request passes through. Refuses (typed `EgressRefusedError`, BEFORE any
     socket opens) any URL whose scheme is not `https` or whose
     `urlsplit(...).hostname` is not exactly `export.arxiv.org` or
     `api.crossref.org` — a real hostname check, not a substring/prefix
     check on the raw URL string (proven against a userinfo-trick lookalike
     URL in the tests). No API key/token/credential/Authorization header is
     ever read, held, or sent — only a descriptive `User-Agent`.
   - `fetch_arxiv_batch`/`parse_arxiv_atom`: ONE batched
     `https://export.arxiv.org/api/query?id_list=<all ids>` request for
     every arXiv id (not one per id), then a pure Atom parse. A requested id
     absent from the response resolves `False`. A VERSIONED requested id
     (`2502.14297v3`) matches ONLY an entry with that exact versioned id;
     an unversioned request matches by base id regardless of the (always
     concrete) version arXiv returns.
   - `fetch_crossref_work`/`parse_crossref_work`: one GET per DOI to
     `https://api.crossref.org/works/<url-quoted doi>`. HTTP 404 ->
     `resolved=False`; any other non-200 -> typed `UpstreamRefusedError`
     naming the status, never a silent `resolved=False`.
   - `read_manifest`/`group_by_resolver`: this script's own minimal,
     decoupled manifest read (it cannot import the frozen evaluator's own
     parser without violating "no mrr.\* import"). An entry with neither
     `identifiers.arxiv` nor `identifiers.doi` is a typed
     `UnresolvableManifestEntryError`, never guessed at.
   - `build_snapshot_document`/`render_snapshot_json`: pure, no network/
     filesystem/wall-clock functions. `resolutions` sorted by `citation_id`;
     `json.dumps(..., indent=2, sort_keys=True) + "\n"` — two renders of the
     same parsed input are byte-identical (AT5).
   - `main`: refuses a pre-existing `--output` (never silently overwrites an
     archived snapshot); maps `ManifestInputError` to exit 2 and every
     refusal (`EgressRefusedError`/`UnresolvableManifestEntryError`/
     `UpstreamRefusedError`) to exit 3.
2. **`corpora/research-records/verification/resolution-snapshot.json`**
   (new, committed archive) — the ONE real, network-touching run of the
   script above, executed once against the committed
   `corpora/research-records/citations.manifest.json` (21 entries, 20 arXiv
   + 1 Crossref DOI, untouched — read-only for this packet).

## Known limitations

- **This is a point-in-time, committed fetch result**, not re-verified live
  (by design, derived_decisions (b)/(e)): if a cited paper were later
  retracted or an arXiv id withdrawn, this snapshot would still say
  "resolved" until a fresh fetch is committed. A nightly re-run belongs to
  R2-T02 (not built), per the packet's own `specification_gaps`.
- **21 is the honest, real number, not 47.** The roadmap draft's "47
  Quellen" is a fetch count (24+23), not a citation count; those fetch lists
  were never committed and remain unauditable. This packet does not close
  that gap — it audits exactly what the records make machine-checkable
  inline (21 identifiers), as the manifest's own `note_on_the_47` states.
- **Existence is not support** (structural, not a gap): a `resolved` status
  means the identifier exists and (for the one entry with a `claimed_title`)
  is correctly titled — it says nothing about whether the source supports
  the claim it is cited for. That is N2-T03, not yet built.
- **The real data never exercises `not_found`/`title_mismatch`/
  `unverifiable`/`malformed`** (21/21 resolve cleanly, and only one entry
  even has a `claimed_title` to potentially mismatch) — those paths are
  proven correct only against the hand-built synthetic/fixture unit tests
  (AT3/AT4), not by the real acceptance data. Expected, not a coverage gap:
  the real record citations genuinely have no problem citations to surface.
- **Crossref detail-string formatting is tuned to the one real DOI in this
  manifest** (`sakana-nature`): the segment-building logic degrades
  gracefully for missing fields (proven by a synthetic sparse-message unit
  test) but has only one real-world data point to validate against.
